## 一、操作系统基础概念

### 1.1 什么是操作系统？

操作系统（Operating System，OS）是管理计算机硬件与软件资源的系统软件，是用户和应用程序与硬件之间的桥梁。常见操作系统：Linux、Windows、macOS。

**核心功能：**
- 进程管理：进程创建、调度、通信、销毁
- 内存管理：虚拟内存、地址映射、内存分配与回收
- 文件系统：文件组织、目录管理、磁盘空间管理
- 设备管理：驱动程序、IO 设备分配与控制
- 提供系统调用接口，屏蔽硬件差异

**一句话总结：**

> 操作系统是硬件资源的管理者，向下管理 CPU、内存、磁盘、网卡等硬件，向上为应用程序提供统一的系统调用接口，让应用程序不用直接操作硬件。

### 1.2 用户态与内核态

CPU 指令按权限分为不同级别（x86 为 Ring 0 ~ Ring 3），操作系统只使用两个级别：

| 状态 | 权限 | 能做什么 |
|------|------|----------|
| 内核态（Ring 0） | 最高权限 | 执行特权指令，直接访问内存、磁盘、网卡等硬件 |
| 用户态（Ring 3） | 受限权限 | 只能访问自己的地址空间，不能直接操作硬件 |

**为什么区分？**
- 防止用户程序随意访问内存、硬件导致系统崩溃。
- 保证多进程之间互不干扰，提高系统安全性和稳定性。

**如何切换？** 用户程序需要操作系统服务时，通过**系统调用**（System Call）从用户态切换到内核态，例如 `read`、`write`、`open`、`fork`、`malloc`（底层 `brk`/`mmap`）。

**面试回答：**

> 用户态和内核态是 CPU 的两种运行级别。用户程序运行在用户态，权限受限，不能直接访问硬件；内核运行在内核态，拥有最高权限。当程序需要 IO、申请内存、创建进程等操作时，通过系统调用陷入内核态，由内核代为完成，执行完再返回用户态。这种隔离机制保证了系统的安全与稳定。

### 1.3 系统调用是什么？

系统调用是操作系统提供给用户程序的编程接口，是用户态进入内核态的唯一合法入口。

**常见系统调用分类：**

| 分类 | 常见系统调用 |
|------|--------------|
| 进程控制 | fork、execve、exit、wait |
| 文件操作 | open、read、write、close、lseek |
| 内存管理 | mmap、munmap、brk |
| 网络通信 | socket、bind、listen、accept、connect、send、recv |
| 信号相关 | kill、sigaction |
| 多路复用 | select、poll、epoll_create、epoll_ctl、epoll_wait |

> 注意：日常调用的 `printf`、Java 的 `FileInputStream.read()` 等库函数/API，最终都会封装为系统调用进入内核。

## 二、进程与线程

### 2.1 什么是进程？

进程（Process）是程序的一次执行实例，是操作系统**资源分配的最小单位**。每个进程有独立的虚拟地址空间、文件描述符表、代码段、数据段、堆栈等。

进程的描述信息保存在 **PCB（Process Control Block，进程控制块）** 中，包含：
- 进程 ID（PID）、进程状态
- 程序计数器、寄存器现场
- 内存指针（页表）
- 打开的文件列表
- 调度优先级等

### 2.2 进程状态转换（五态模型）

```text
                    创建完成
        新建 ──────────────────► 就绪 ◄────────────────┐
                                 │                     │
                                 │ 获得 CPU            │ 时间片用完 / 被抢占
                                 ▼                     │
                              运行 ────────────────────┘
                                 │
                                 │ 等待 IO / 事件
                                 ▼
                              阻塞 ─── IO 完成 ──► 就绪
                                 │
                                 │ 执行结束
                                 ▼
                              终止
```

| 状态 | 含义 |
|------|------|
| 新建 | 进程正在被创建 |
| 就绪 | 万事俱备，只等 CPU 调度 |
| 运行 | 正在占用 CPU 执行 |
| 阻塞 | 等待 IO、锁、事件，**即使 CPU 空闲也不会运行** |
| 终止 | 进程执行完毕或被杀死 |

**面试高频考点：** 运行态不会直接变为就绪态以外的状态而不经过调度；阻塞态不能直接进入运行态，必须先回到就绪态等待调度。

### 2.3 什么是线程？

线程（Thread）是进程内的一条执行流，是操作系统 **CPU 调度的最小单位**。同一进程的多个线程共享进程的地址空间、文件描述符、堆内存，但每个线程有独立的：
- 程序计数器（PC）
- 寄存器集合
- 栈（函数调用栈、局部变量）

### 2.4 进程 vs 线程（高频对比题）

| 对比项 | 进程 | 线程 |
|--------|------|------|
| 定位 | 资源分配的最小单位 | CPU 调度的最小单位 |
| 地址空间 | 独立虚拟地址空间 | 共享所属进程的地址空间 |
| 资源开销 | 创建/销毁开销大 | 开销小（只需栈、寄存器等） |
| 上下文切换 | 切换慢（要切页表、刷 TLB） | 切换快（地址空间不变） |
| 通信方式 | IPC：管道、共享内存、消息队列等，成本高 | 直接读写共享变量，成本低（需同步） |
| 崩溃影响 | 一个进程崩溃一般不影响其他进程 | 一个线程崩溃可能导致整个进程崩溃 |
| 适用场景 | 需要隔离、独立容错 | 高并发、共享数据频繁的并行计算 |

**面试回答：**

> 进程是资源分配的最小单位，线程是 CPU 调度的最小单位。进程有独立的地址空间，线程共享进程的地址空间，所以线程创建和切换的开销比进程小，线程间通信直接读写共享内存即可，但需要加锁保证线程安全；进程间通信必须借助 IPC 机制。一个进程崩溃通常不影响其他进程，而一个线程崩溃往往会导致整个进程崩溃。

### 2.5 什么是协程？

协程（Coroutine）是**用户态的轻量级线程**，由用户程序自己调度，不经过内核。

| 对比项 | 线程 | 协程 |
|--------|------|------|
| 调度者 | 操作系统内核 | 用户程序（运行时/语言库） |
| 切换成本 | 微秒级，有内核态切换 | 纳秒级，纯用户态切换 |
| 栈大小 | MB 级 | KB 级，可动态增长 |
| 典型实现 | Java 线程、pthread | Go goroutine、Python asyncio、Kotlin coroutine |

**适用场景：** 海量 IO 并发（如 Go 的 goroutine 可轻松创建几十万个），但计算密集型任务协程无法利用多核（单个线程内的协程本质串行）。

### 2.6 守护进程、僵尸进程、孤儿进程

| 概念 | 含义 | 危害与处理 |
|------|------|------------|
| 守护进程 | 后台运行、脱离终端的进程（如 nginx、redis-server） | 正常服务形态 |
| 僵尸进程 | 子进程已退出，但父进程没有 `wait()` 回收其 PCB，状态为 `Z` | 占用 PID 资源，积累多了无法创建新进程；需杀死父进程让其被 init 收养回收 |
| 孤儿进程 | 父进程先退出，子进程被 init（PID 1）收养 | 无害，init 会负责回收 |

**面试高频：** 僵尸进程怎么排查？

> `ps aux | grep Z` 或 `ps -ef | grep defunct` 找到僵尸进程，再定位其父进程。解决方法是重启/杀死父进程，让僵尸子进程被 init 收养后回收；根因是父进程代码没有正确处理 `SIGCHLD` 或调用 `wait/waitpid`。

## 三、进程间通信（IPC）

### 3.1 常见 IPC 方式

| 方式 | 原理 | 优点 | 缺点 | 适用场景 |
|------|------|------|------|----------|
| 管道 Pipe | 内核缓冲区，半双工，父子进程间 | 简单 | 只能单向、有亲缘关系限制 | `ps aux | grep xxx` |
| 命名管道 FIFO | 文件系统中的管道文件 | 任意进程可用 | 仍是半双工、效率一般 | 本地简单通信 |
| 消息队列 | 内核维护的消息链表 | 有格式、可随机读取 | 有大小限制、拷贝两次 | 小数据量、解耦 |
| 共享内存 | 多进程映射同一块物理内存 | **最快，无需拷贝** | 需自己配合同步（信号量） | 大数据量、高频通信 |
| 信号量 | 计数器，P/V 操作 | 做同步互斥 | 不传输数据 | 配合共享内存 |
| 信号 Signal | 异步通知（如 SIGKILL） | 简单异步 | 信息量极少 | 进程控制通知 |
| Socket | 网络协议栈 | **可跨机器** | 开销最大 | 跨机/本机通用通信 |

### 3.2 高频问题：哪种 IPC 最快？

> **共享内存最快**。因为共享内存把同一块物理内存映射到多个进程的虚拟地址空间，进程读写时不需要经过内核拷贝数据；而管道、消息队列、Socket 都需要"用户态 → 内核态 → 用户态"两次数据拷贝。共享内存的缺点是本身不提供同步机制，需要配合信号量或互斥锁使用。

### 3.3 线程间如何同步？

- 互斥锁（Mutex）：同一时刻只允许一个线程进入临界区
- 读写锁（ReadWriteLock）：读共享、写独占，适合读多写少
- 信号量（Semaphore）：控制同时访问资源的线程数量
- 条件变量（Condition）：配合互斥锁实现等待/通知（如 Java `wait/notify`、生产者消费者模型）
- CAS 原子操作：无锁编程（如 Java `AtomicInteger`）
- CountDownLatch / CyclicBarrier 等 JUC 工具

## 四、内存管理基础

### 4.1 什么是虚拟内存？

虚拟内存（Virtual Memory）是给每个进程提供的一套**独立的、连续的、比物理内存大得多的虚拟地址空间**，由操作系统和 MMU（内存管理单元）负责把虚拟地址翻译成物理地址。

**为什么需要虚拟内存？**
1. **进程隔离**：每个进程看到独立的地址空间，互不干扰，一个进程崩溃不影响其他进程。
2. **内存扩展**：可以把不常用的内存页换出到磁盘（Swap），让程序使用超过物理内存的内存。
3. **简化编程**：程序可以使用连续的虚拟地址，不用关心物理内存碎片和实际位置。
4. **内存共享**：多个进程的虚拟页可以映射到同一物理页（共享库、共享内存）。
5. **按需加载**：程序不必一次性全部装入内存（缺页中断按需调入）。

### 4.2 分页与分段

| 对比项 | 分段 | 分页 |
|--------|------|------|
| 划分依据 | 按逻辑：代码段、数据段、堆段、栈段 | 按固定大小（常见 4KB） |
| 大小 | 不固定 | 固定 |
| 碎片问题 | 产生外部碎片 | 产生内部碎片，无外部碎片 |
| 地址空间 | 二维（段号 + 段内偏移） | 一维（页号 + 页内偏移） |
| 现状 | x86 中段式基本弱化 | 主流方式，Linux 采用 |

> Linux 实际采用**段页式**结合：逻辑上分段（代码段/数据段），物理管理上分页。面试答分页为主即可。

### 4.3 页面置换算法（高频）

当物理内存不足、发生缺页时需要淘汰页面，常见算法：

| 算法 | 原理 | 特点 |
|------|------|------|
| OPT 最佳置换 | 淘汰未来最长时间不再使用的页 | 理论最优，无法实现，作为对比基准 |
| FIFO 先进先出 | 淘汰最早进入内存的页 | 可能出现 Belady 异常（加页框反而缺页增多） |
| **LRU 最近最少使用** | 淘汰最长时间没被访问的页 | 性能好，面试最高频；Redis 内存淘汰也用 LRU |
| LFU 最不经常使用 | 淘汰使用次数最少的页 | 能识别长期热点，Redis 4.0 支持 |
| Clock 时钟算法 | LRU 近似实现，环形链表 + 访问位 | 工程上常用，实现简单 |

**高频问题：LRU 怎么实现？**

> 哈希表 + 双向链表。哈希表保证 O(1) 查找，双向链表维护访问顺序：访问一个节点就把它移到链表头部，链表尾部就是最近最少使用的节点，容量满时淘汰尾部节点。LeetCode 146 原题。

### 4.4 内部碎片与外部碎片

- **内部碎片**：分配给进程的内存块中没用完的部分（分页产生，页大小固定）。
- **外部碎片**：空闲内存被分割成许多小块，总量够但不连续（分段/动态分区产生）。Linux 用**伙伴系统**缓解外部碎片。

## 五、死锁

### 5.1 什么是死锁？

死锁（Deadlock）是指多个进程/线程互相持有对方需要的资源，并且都在等待对方释放，导致所有参与者永远无法继续执行的状态。

```text
线程 A：持有锁 1，等待锁 2
线程 B：持有锁 2，等待锁 1
=> 互相等待，形成死锁
```

### 5.2 死锁产生的四个必要条件（必背）

1. **互斥**：资源同一时刻只能被一个进程占用。
2. **持有并等待**：进程持有至少一个资源，同时等待其他被占用的资源。
3. **不可剥夺**：已分配的资源不能被强制抢走，只能主动释放。
4. **循环等待**：存在进程资源的循环等待链（A 等 B，B 等 C，C 等 A）。

> 四个条件**缺一不可**，破坏任意一个即可避免死锁。

### 5.3 死锁的处理策略

| 策略 | 思路 | 典型手段 |
|------|------|----------|
| 死锁预防 | 破坏四个必要条件之一 | 一次性申请所有资源（破坏持有并等待）；按固定顺序加锁（破坏循环等待）；允许剥夺 |
| 死锁避免 | 分配前判断是否安全 | 银行家算法（判断系统是否处于安全状态） |
| 死锁检测 + 解除 | 允许死锁发生，定期检测 | 资源分配图检测环；解除方式：杀死进程、剥夺资源、回滚 |

### 5.4 工程实践中如何避免死锁？（高频）

1. **固定加锁顺序**：所有线程按相同顺序获取多把锁（最常用）。
2. **使用超时锁**：如 Java `tryLock(timeout)`，超时后放弃并重试。
3. **减小锁粒度、缩短持锁时间**：不要在持锁期间调用外部接口、做 IO。
4. **一个锁能搞定就不要用多个锁**。
5. **使用无锁结构**：CAS、并发容器。
6. 数据库层面：保持事务短小、按相同顺序访问行、加索引避免锁升级。

**面试回答：**

> 死锁需要同时满足互斥、持有并等待、不可剥夺、循环等待四个条件。工程上最常用的避免手段是固定加锁顺序破坏循环等待，以及使用 `tryLock` 超时机制。排查 Java 死锁可以用 `jstack <pid>` 导出线程快照，jstack 会自动检测并输出 `Found one Java-level deadlock` 及死锁涉及的线程和锁。

### 5.5 银行家算法（了解）

银行家算法是死锁避免算法：系统在分配资源前，先模拟分配，判断分配后系统是否仍处于**安全状态**（存在一个安全序列，让所有进程都能顺利完成），安全才分配，否则让请求等待。

## 六、文件系统基础

### 6.1 文件描述符（fd）

文件描述符（File Descriptor）是内核为进程打开的文件/IO 资源分配的一个**非负整数索引**，是进程访问文件、Socket、管道的句柄。

每个进程默认打开 3 个 fd：

| fd | 名称 | 含义 |
|----|------|------|
| 0 | stdin | 标准输入 |
| 1 | stdout | 标准输出 |
| 2 | stderr | 标准错误输出 |

> `2>&1` 的含义：把标准错误（fd 2）重定向到标准输出（fd 1）指向的位置，常用于 `nohup java -jar app.jar > app.log 2>&1 &`。

**高频问题：** fd 上限相关线上问题

> Linux 默认单进程 fd 上限常为 1024（`ulimit -n` 查看）。高并发服务（Nginx、Java 服务）连接数大时容易报 `Too many open files`，需要调大 `ulimit -n`，或排查是否存在连接/文件句柄泄漏。

### 6.2 inode 是什么？

inode（索引节点）是文件系统中存储**文件元数据**的结构，包含：文件大小、属主、权限、时间戳、指向数据块的指针等。**文件名不存储在 inode 中**，而是存储在目录文件中（目录 = 文件名 → inode 号的映射表）。

- `ls -i` 可查看 inode 号。
- 删除文件本质是删除目录中的文件名映射并把 inode 引用计数减 1。
- 磁盘空间没满但报 `No space left on device`，可能是 **inode 耗尽**（大量小文件），用 `df -i` 查看。

### 6.3 硬链接与软链接

| 对比项 | 硬链接 | 软链接（符号链接） |
|--------|--------|--------------------|
| 本质 | 同一个 inode 的多个文件名 | 独立文件，内容是目标文件路径 |
| inode 号 | 与源文件相同 | 不同 |
| 跨文件系统 | 不支持 | 支持 |
| 链接目录 | 不支持 | 支持 |
| 源文件删除后 | 仍可访问（inode 引用计数 > 0） | 失效（悬空链接） |
| 创建命令 | `ln source target` | `ln -s source target` |

### 6.4 PageCache（页缓存）

Linux 会把磁盘文件的内容缓存在内存中，称为 PageCache：
- **读**：先查 PageCache，命中则不走磁盘（这就是 Redis/Kafka 快的重要原因之一）。
- **写**：先写 PageCache 即返回（write back 回写），由内核线程（pdflush）或 `fsync` 强制刷盘。

> 面试联想：`free` 命令中 `buff/cache` 列就是 PageCache；MySQL 的 buffer pool、Kafka 依赖 PageCache 顺序写，都是围绕它做的设计。`fsync` 相关：`appendfsync everysec`（Redis）、RocketMQ 刷盘策略，本质都是"什么时候把 PageCache 刷到磁盘"。

## 七、操作系统面试高频问题速记

| 问题 | 一句话答案 |
|------|------------|
| 进程和线程区别 | 进程是资源分配单位（独立地址空间），线程是调度单位（共享进程资源） |
| 进程间通信方式 | 管道、消息队列、共享内存（最快）、信号量、信号、Socket |
| 线程间同步方式 | 互斥锁、读写锁、信号量、条件变量、CAS |
| 死锁四个条件 | 互斥、持有并等待、不可剥夺、循环等待 |
| 如何避免死锁 | 固定加锁顺序、超时锁、减少锁粒度 |
| 虚拟内存作用 | 进程隔离、扩大可用内存、简化地址管理、支持共享 |
| 页面置换算法 | OPT、FIFO、LRU（哈希表+双向链表）、LFU、Clock |
| 用户态内核态区别 | 权限级别不同，系统调用是切换入口 |
| 系统调用举例 | read、write、fork、mmap、socket、epoll |
| 僵尸进程 | 子进程退出父进程未 wait，杀父进程由 init 回收 |
| 硬链接软链接区别 | 硬链接共享 inode，软链接存路径、可跨文件系统 |
| LRU 实现 | 哈希表 + 双向链表，O(1) 读写，尾部淘汰 |
